# MetricHUD

> ⚠️ **Early Development Build**
>
> MetricHUD is under active development and is not yet feature complete.

A lightweight, customizable metrics HUD for **Guild Wars 2**.

The goal is simple:

> **Show the information the player wants—and nothing they don't.**

MetricHUD is being developed as a Nexus addon with the long-term goal of providing useful combat metrics, encounter information, and optional player-training tools without overwhelming the screen.

> **ArcDPS gives you the data. MetricHUD helps you learn from it.**

# ============================================================
# 5. LIVE VS LAST-FIGHT METRICS
# ============================================================

MetricHUD separates information about the current encounter from information about the most recently completed encounter.

Live metrics include:

```text
DPS
Damage
Downed Count
Death Count
```

Completed-fight metrics include:

```text
Last Fight DPS
Last Fight Time
Last Fight Damage
Last Fight Downs
Last Fight Deaths
```

Current-fight Downed Count and Death Count reset when the next combat encounter begins.

Last Fight Downs and Last Fight Deaths remain available until another encounter finishes.

Example:

```text
Fight #1 ends:
Downed Count: 1
Death Count: 1
Last Fight Downs: 1
Last Fight Deaths: 1

Fight #2 begins:
Downed Count: 0
Death Count: 0
Last Fight Downs: 1
Last Fight Deaths: 1

Fight #2 ends with no downs or deaths:
Last Fight Downs: 0
Last Fight Deaths: 0
```

This rollover behavior has been verified in Guild Wars 2.

# 8. DAMAGE ATTRIBUTION
# ============================================================

MetricHUD's current live damage model includes:

```text
Player Direct Damage
+
Player Condition / Buff Damage
+
Owned-Agent Direct Damage
+
Owned-Agent Condition / Buff Damage
=
Accepted Player Damage
```

Player-owned agent handling allows qualifying pet and minion damage to be attributed back to the player.

Controlled testing has included:

- Player-only damage
- Pet-only damage
- Direct damage
- Condition damage
- Bleeding damage
- Skill attribution
- Damage timing
- DPS comparison against ArcDPS

No arbitrary correction factor is used simply to force MetricHUD's result to match another meter.


# ============================================================
# 9. DPS TIMING MODEL
# ============================================================

Several combat-duration models were investigated during development.

The current live DPS timing model uses:

```text
ArcDPS ENTERCOMBAT timestamp
        ↓
Last accepted damage timestamp
```

Testing found this model produced the closest verified agreement with ArcDPS while preserving a clear and reproducible calculation.

The DPS calculation is conceptually:

```text
Accepted Damage
÷
Time from ArcDPS ENTERCOMBAT to Last Accepted Damage
=
DPS
```

The same timing model is used when completed-fight information is captured.

MetricHUD intentionally favors a verified calculation model over arbitrary correction factors.
